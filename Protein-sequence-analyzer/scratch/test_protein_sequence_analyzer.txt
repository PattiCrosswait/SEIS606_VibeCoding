Protein Sequence Analyzer Test Cases

Test Case 1: Accept a valid raw amino-acid sequence
Given the analyzer page is open
When the user enters "MKWVTFISLLLLFSSAYSRGVFRRDTHKSEIAHRFKDLGE" and selects Analyze sequence
Then the sequence is accepted as valid
And length, molecular weight, theoretical pI, hydrophobicity, composition, and residue map are updated
And results are labeled with units and understandable names

Test Case 2: Accept a FASTA record
Given the analyzer page is open
When the user enters a FASTA header followed by a valid sequence and selects Analyze sequence
Then the FASTA header is excluded from the analysis
And the sequence is analyzed as the equivalent raw sequence
And the original input remains available when the interface displays it separately

Test Case 3: Normalize lowercase and whitespace
Given the analyzer page is open
When the user enters a valid sequence using lowercase letters, spaces, and line breaks
And selects Analyze sequence
Then permitted case and whitespace differences do not cause validation failure
And the normalized sequence produces the same results as the uppercase sequence

Test Case 4: Reject an empty sequence
Given the sequence input is empty
When the user selects Analyze sequence
Then a clear corrective validation message is shown
And no plausible-looking metrics are displayed or updated
And the input remains editable without silently replacing existing valid results

Test Case 5: Reject unsupported residues
Given the analyzer page is open
When the user enters "MKWVZ123!" and selects Analyze sequence
Then validation identifies the unsupported residue or characters
And analysis does not run
And stale results are not presented as current
And the user can correct the input without losing the sequence

Test Case 6: Handle a single-residue sequence
Given the analyzer page is open
When the user enters "A" and selects Analyze sequence
Then the reported length is 1 residue
And molecular weight and composition are calculated without an error
And the residue map and metrics remain readable

Test Case 7: Analyze a long representative sequence
Given the analyzer page is open
When the user pastes a valid sequence of at least 1,000 residues
And selects Analyze sequence
Then analysis completes without freezing the interface or crashing
And results remain accurate and readable
And the sequence visualization does not create uncontrolled layout overflow

Test Case 8: Verify deterministic results
Given a valid sequence is available
When the user analyzes the sequence twice
Then both analyses produce identical displayed metrics
And no duplicate or conflicting result state appears
And the analysis version is shown when versioned calculations are supported

Test Case 9: Verify residue composition totals
Given a valid sequence containing hydrophobic, polar, charged, and special residues
When the user reviews the composition groups
Then the group counts sum to the total sequence length
And every residue is assigned to exactly one displayed group

Test Case 10: Verify safe rendering of user input
Given the analyzer page is open
When the user enters "<script>alert(1)</script>" and selects Analyze sequence
Then the content is treated as invalid input and rendered as text only
And no script executes
And no unexpected markup is inserted into the page

Test Case 11: Detect a likely signal peptide
Given signal-peptide prediction is supported
And a sequence with a hydrophobic N-terminal signal region is available
When the user analyzes the sequence
Then the predicted signal peptide and residue range are reported
And the prediction method or source is identified
And confidence or limitations are included

Test Case 12: Detect likely transmembrane helices
Given transmembrane prediction is supported
And a sequence contains a long hydrophobic membrane-spanning segment
When the user analyzes the sequence
Then a likely transmembrane region is reported with start and end positions
And the prediction is distinguishable from confirmed experimental evidence

Test Case 13: Report no prediction when evidence is insufficient
Given a soluble sequence without a strong signal peptide or membrane segment is available
When the user analyzes the sequence
Then the application reports no strong prediction rather than inventing a feature
And the result explains that absence of a prediction is not proof of biological absence

Test Case 14: Identify known motifs and domains
Given motif or domain detection is enabled
And a sequence with a known motif is available
When the user analyzes the sequence
Then matching motifs or domains are listed with names and residue positions
And matches include the database or algorithm source
And an appropriate confidence or score is displayed

Test Case 15: Display low-complexity or disordered regions
Given a sequence containing a low-complexity or disorder-prone region is available
When the user analyzes the sequence
Then the predicted region is highlighted with a clear legend
And the output identifies it as a prediction
And it is not presented as experimentally confirmed

Test Case 16: Display secondary-structure predictions
Given secondary-structure prediction is supported
When the user analyzes a valid sequence
Then predicted helix, sheet, and coil regions are shown with positions
And a legend explains the output without relying on color alone

Test Case 17: Handle prediction service failure
Given the prediction service is unavailable or returns an error
When the user requests a biological prediction
Then a clear loading, failure, or retry state is shown
And locally computed core metrics remain available
And no failed prediction is shown as a valid result

Test Case 18: Preserve prediction provenance
Given at least one biological prediction is available
When the user opens the prediction details
Then the method, database or model, version, score or confidence, and limitations are visible
And calculated facts can be distinguished from biological interpretation

Test Case 19: Compare two saved sequences
Given two valid sequences are saved in the protein library
When the user opens Compare and selects both sequences
Then both sequences appear side by side
And length, molecular weight, pI, hydrophobicity, composition, and supported metrics are comparable
And differences are labeled clearly without relying only on color

Test Case 20: Run pairwise sequence alignment
Given two valid sequences are available
When the user starts a pairwise alignment
Then matches, mismatches, insertions, and deletions are displayed with positions
And the alignment completes for sequences of different lengths
And the scoring method and gap assumptions are available

Test Case 21: Run multiple-sequence alignment
Given at least three valid sequences are available
When the user selects the sequences and starts a multiple-sequence alignment
Then all selected sequences are aligned and labeled
And conserved positions are identifiable
And invalid sequence errors are reported clearly

Test Case 22: Search an external protein database
Given database lookup is configured and network access is available
When the user searches with a valid accession or sequence
Then matching records show name, accession, organism, and relevant length information
And the source database and retrieval time are identified
And results can be opened without losing the current analysis

Test Case 23: Handle no database matches
Given database lookup is available
When the user searches with a valid sequence or accession that has no known match
Then a clear no-results state is shown
And the user can revise the search or return to the analysis
And no unrelated result is presented as a match

Test Case 24: Filter and search the saved protein library
Given the library contains proteins with different names, accessions, and types
When the user searches by name, searches by accession, and filters by protein type
Then each filter updates the displayed rows correctly
And empty results show an informative empty state
And clearing the filters restores the complete library

Test Case 25: Compare sequences with missing optional metadata
Given a saved sequence has no accession, type, or prediction metadata
When the user adds it to a comparison
Then missing values are displayed as unavailable rather than causing an error
And available sequence-level comparisons still work

Test Case 26: Generate a reproducible comparison report
Given a comparison or alignment has completed
When the user exports the comparison report and opens it
Then the report includes sequence identifiers, input sequences or references, methods, settings, results, and analysis version
And exported values match the values shown in the application

Test Case 27: Load a sample sequence
Given the analyzer page is open and sample sequences are available
When the user selects a sample sequence
Then the sample is loaded into the input
And the sequence is analyzed or ready for analysis according to the interface contract
And the user receives a clear status message

Test Case 28: Navigate between workspace sections
Given the application is open
When the user opens Analyze, Saved sequences, Compare, Reports, and Preferences
Then the selected section has a clear active state
And navigation does not unexpectedly discard the current sequence or saved work
And unavailable sections communicate their status rather than appearing broken

Test Case 29: Use the application with a keyboard
Given the application is open
When the user navigates through inputs, buttons, menus, tables, and links using Tab and Shift+Tab
And activates controls using Enter or Space
Then every interactive control is reachable in a logical order
And focus is visible
And no essential action requires a mouse

Test Case 30: Verify accessible labels and status messages
Given the application is open
When the user inspects inputs, charts, buttons, validation messages, and result regions with assistive technology
Then inputs and controls have meaningful accessible names
And validation and analysis updates are announced or exposed as status changes
And charts and color-coded residue groups have text or pattern alternatives

Test Case 31: Verify responsive mobile layout
Given the application is open
When the user uses it at a narrow mobile viewport and analyzes a sequence
Then core input and results remain available without overlapping content
And text and controls fit their containers
And tables and long sequences have an intentional responsive or scrolling treatment

Test Case 32: Verify responsive desktop layout
Given the application is open
When the user uses it at a wide desktop viewport and resizes across common desktop widths
Then panels remain aligned and readable
And no content is clipped or pushed outside the viewport
And layout transitions do not lose entered data or analysis state

Test Case 33: Show analysis progress and recovery
Given an analysis or external prediction can take measurable time
When the user starts the operation and a failure is forced or simulated
Then a loading or progress state is visible
And duplicate submissions are prevented or handled safely
And failure includes a useful message and retry path
And a successful retry replaces the failed state with current results

Test Case 34: Download a complete report
Given a valid sequence has been analyzed
When the user selects Download report and opens the downloaded file
Then the report has a meaningful filename
And it includes the input or identifier, normalized sequence, metrics, charts or tables, methods, assumptions, and limitations
And the report matches the current analysis

Test Case 35: Preserve data after validation failure
Given a valid sequence has been entered and analyzed
When the user adds an invalid character and selects Analyze sequence
Then the validation error is shown
And the edited input remains intact for correction
And previous results are marked stale or remain available without being mislabeled as current

Test Case 36: Maintain readable contrast and non-color cues
Given the application is open
When the user reviews validation states, residue groups, charts, buttons, and active navigation in grayscale or with color-vision simulation
Then status and residue categories remain understandable through text, labels, symbols, patterns, or tooltips
And text and controls meet the project's contrast requirements

Test Case 37: Prevent unbounded work during typing
Given the analyzer supports live validation or character counting
When the user pastes a long sequence and repeatedly types, deletes, and pastes
Then the input remains responsive
And expensive analysis is not repeatedly triggered without an explicit action unless intentionally debounced
And the browser remains usable during edits

Test Case 38: Keep user state during navigation and refresh-safe actions
Given a sequence is entered and analysis results are visible
When the user navigates to another workspace section, returns, and triggers a report download
Then the application preserves or clearly communicates what state is retained
And downloading or navigation does not unexpectedly clear the current sequence
And any state that cannot be restored is explained to the user
